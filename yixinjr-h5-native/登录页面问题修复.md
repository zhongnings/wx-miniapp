# 登录页面问题修复说明

## 🐛 发现的问题

### 问题1：文字全部显示到一行
**现象：** "我已知晓并同意《用户协议》和《隐私协议》" 显示在一行

**原因：**
- H5 中 `text` 标签默认是 `inline` 元素
- `white-space` 可能被设置为 `nowrap`
- `display: inline` 导致不换行

**修复方案：**
1. 修改 `.agreement-text` 样式，添加换行属性
2. 修改 `.agreement-label` 对齐方式为 `flex-start`
3. 在 `h5-fix.css` 中添加全局文本换行规则

---

### 问题2：checkbox 不显示
**现象：** "我已知晓" 前面的复选框看不见

**原因：**
- H5 中 uni-app 的 checkbox 组件渲染方式不同
- 需要显式设置 checkbox 的样式
- 可能被 `transform: scale(0)` 或 `opacity: 0` 隐藏

**修复方案：**
1. 在 `h5-fix.css` 中添加 checkbox 显示样式
2. 设置 `uni-checkbox-input` 的边框和背景色
3. 设置选中状态的样式

---

### 问题3：协议文档404
**现象：** 点击《用户协议》和《隐私协议》显示404

**原因：**
- H5 环境下，文档路径 `/agreements/user-agreement.docx` 会请求到前端服务器（localhost:8080）
- 但文档实际在后端服务器（localhost:8081）
- 需要区分 H5 和小程序的文档访问方式

**修复方案：**
1. H5 环境：使用 `window.location.origin` 获取当前域名
2. 如果文档在后端，需要使用完整的后端地址
3. 修改 `previewDocument` 方法，使用条件编译

### 3. 修复协议文档404问题

**修改文件：** `pages/login/index.vue`

**原代码：**
```javascript
previewDocument(fileUrl, title) {
  // 获取请求工具
  const req = uni.$request || require('../../utils/request.js');
  const baseUrl = req.BASE_URL || '';
  const fullUrl = isAbsolute ? fileUrl : `${baseUrl}${fileUrl}`;
  
  // #ifdef H5
  window.open(fullUrl, '_blank');
  // #endif
}
```

**修复后：**
```javascript
previewDocument(fileUrl, title) {
  if (!fileUrl) {
    uni.showToast({
      title: '协议文件地址未配置',
      icon: 'none'
    });
    return;
  }
  
  // #ifdef H5
  // H5 平台：直接在新窗口打开文档
  // 使用当前页面的协议和主机名
  const currentOrigin = window.location.origin;
  const fullUrl = fileUrl.startsWith('http') ? fileUrl : `${currentOrigin}${fileUrl}`;
  
  logger.info(`打开协议文档: ${fullUrl}`);
  window.open(fullUrl, '_blank');
  // #endif
  
  // #ifndef H5
  // 小程序平台：下载并打开文档
  // ... 小程序代码保持不变
  // #endif
}
```

**关键改动：**
1. 使用 `window.location.origin` 获取当前域名
2. 如果 fileUrl 不是绝对路径，拼接当前域名
3. 添加日志输出，方便调试

## 🔧 协议文档访问的两种方案

### 方案1：文档放在前端静态资源（推荐）⭐

**步骤：**

1. **复制文档到前端项目**
```bash
# 创建目录
mkdir -p /d/workcode/miniapp/yixinjr-h5-native/static/agreements

# 复制文档
cp /d/workcode/miniapp/target/classes/agreements/*.docx /d/workcode/miniapp/yixinjr-h5-native/static/agreements/
```

2. **修改文档路径**

在 `pages/login/index.vue` 中：
```javascript
data() {
  return {
    userAgreementUrl: '/static/agreements/user-agreement.docx',
    privacyPolicyUrl: '/static/agreements/privacy-policy.docx',
  };
}
```

3. **优点：**
- ✅ 不需要后端支持
- ✅ 访问速度快
- ✅ 不会有跨域问题
- ✅ 前端独立部署

---

### 方案2：文档放在后端（需要配置）

**步骤：**

1. **修改文档路径为完整后端地址**

在 `pages/login/index.vue` 中：
```javascript
data() {
  return {
    userAgreementUrl: 'http://localhost:8081/agreements/user-agreement.docx',
    privacyPolicyUrl: 'http://localhost:8081/agreements/privacy-policy.docx',
  };
}
```

2. **后端需要配置静态资源访问**

在 Spring Boot 配置中：
```java
@Configuration
public class WebMvcConfig implements WebMvcConfigurer {
    @Override
    public void addResourceHandlers(ResourceHandlerRegistry registry) {
        registry.addResourceHandler("/agreements/**")
                .addResourceLocations("classpath:/agreements/");
    }
}
```

3. **配置 CORS（如果前后端分离）**

```java
@Configuration
public class CorsConfig {
    @Bean
    public CorsFilter corsFilter() {
        CorsConfiguration config = new CorsConfiguration();
        config.addAllowedOrigin("http://localhost:8080");
        config.addAllowedMethod("*");
        config.addAllowedHeader("*");
        
        UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
        source.registerCorsConfiguration("/agreements/**", config);
        
        return new CorsFilter(source);
    }
}
```

4. **缺点：**
- ⚠️ 需要后端支持
- ⚠️ 可能有跨域问题
- ⚠️ 依赖后端服务
